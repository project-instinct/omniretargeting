# TRUMANS 几何与约束构建提速（2026-09-24）

本轮继续优化之前耗时 44 分 14 秒的 1304 帧片段。比较口径仍然是后处理、
局部修复、全身修正三个阶段之和，不包含前面的三次序列拟合、人体模型推理
或视频渲染。配置、场景比例、采样点、帧间细分和所有验收预算保持不变。

## 瓶颈证据

冻结修改前的源码后，在相同真实场景的前 96 帧、2,431 个帧间姿态上进行
`cProfile` 剖析，共查询 2,527 个姿态，几何验收耗时 80.016 秒。

| 路径 | 累计时间 | 说明 |
| --- | ---: | --- |
| 胶囊／球体与有限三角形查询 | 44.814 s | 包含下面的最近点计算 |
| 线段／三角形最近点计算 | 34.440 s | 38,667 次调用，重复分配大量小数组 |
| 场景距离及绕数内外判断 | 32.522 s | 116 次场景查询 |
| 全部 MuJoCo FK 调用 | 0.476 s | 10,108 次调用 |

父子项不能相加。这份剖析不是优化器耗时；它支持优先减少几何计算量，不能据此
声称整个优化数学模型错误。旧完整记录中的全身 14 个窗口均未接受候选，却各花费
35–94 秒，也提示需要区分建模、求解和验收，而不能只报告一个全身阶段总时间。

## 实现

1. `triangle_candidates.py` 在原 R-tree 粗筛后增加保守距离界筛选。
   线段包围盒到三角形包围盒的距离提供下界；任一候选三角形顶点到线段的
   距离提供上界。只剔除下界严格大于上界的三角形。保留全部轴穿面候选、
   数值零距离带及并列候选，因此不会遗漏更深的穿面退出向量或其歧义。
2. `geometry_query.py` 将同一姿态的胶囊／球体查询合并，批量执行原来的
   端点／面、线段／边、线段／面最近点算法。固定三角形、包围盒和 R-tree
   只读取一次。仍然使用原始面编号、原始排序和完整有限三角形。
3. `triangle_capsule.py` 保留每个共享轴分组的原始点积运算顺序。
   初版直接使用批量点积虽然只产生微小舍入差异，但会改变少量共面并列见证的
   面编号；该版本未采用。最终分组路径保持这些见证的确定性。
4. `_refinement/guard.py` 的场景约束在线下无限查询预算模式下复用批量查询，
   避免每一帧单独重建绕数加速结构。有限预算保持原来的顺序及计数检查。
   共用批量大小为最多约 104 万个逻辑查询点；这是内存工作集，不是几何降采样。
5. 全身窗口报告分别记录运动物体查询、线性化、约束构建／求解和候选验收耗时；
   求解报告另外记录 CVXPY 编译和数值求解耗时，供后续定位剩余瓶颈。
6. 全身候选先通过固定的姿态、逐关节连续性、接触与静态几何验收，再按需
   计算原轨迹目标值。所有候选都不满足硬约束时，不再计算无用的目标值。
   候选到达目标值比较时，仍使用同一个原始目标值和原来的回退序列。
7. 窗口组合的最终轨迹与固定参考逐项相同时，复用已完成的静态几何报告和
   已通过的运动物体完整检查。仍执行固定序列预算、运动保真、几何非退化
   比较与已知场景采样保护。发生任何轨迹变化时重新检查，失败或未完成的
   运动物体检查不能复用。报告记录复用次数。

libigl 的 [fast winding number 实现](https://github.com/libigl/libigl/blob/v2.6.0/include/igl/fast_winding_number.cpp)
提供预计算和查询分离的 C++ 接口，但本机 Python 接口只暴露合并调用。
本轮批量化复用现有安装，没有新增本地 C++ 编译依赖，也未替换绕数判定方法。

## 验证方法和产物

可复现脚本及修改前源码在 `out/algorithm_speed_20260924/`。

通过真实 `OmniRetargeter` 主流程复跑。三份已完成的序列拟合按原脚本的
`resume_through_stage=2` 路径恢复，并校验输入人体数组。每次复跑使用新的
进程和空几何缓存；没有加载已经算好的碰撞结果冒充加速。

最终 96 帧剖析为 **29.055 秒**（原来 80.016 秒，约 2.75 倍）。

### 剩余耗时

全身阶段中，运动物体初始完整检查占 **192.005 秒**，各窗口运动物体几何行
合计 **129.843 秒**，约占该阶段 78%。线性化仅 **0.797 秒**，约束构建与求解
合计 **75.495 秒**，候选验收 **5.271 秒**。未变化的最终结果复用了 1 次静态
和 1 次运动物体基准检查。证据支持继续优化几何查询与加速结构生命周期，
不支持通过放松运动质量约束来缩短时间。

这 75.495 秒中，CVXPY 编译合计 13.008 秒，数值求解合计 33.821 秒；其余是
构建约束等开销。不能将整段慢归因于数值求解器本身。

新增回归还覆盖硬约束拒绝时不计算目标值、部分回退后的目标值不变、真正可行的
运动物体修正仍能接受、变化轨迹必须重查、失败基准不能复用，以及多个胶囊／球体
和场景组件的全部见证字段与未裁剪、逐轴计算完全相同。
