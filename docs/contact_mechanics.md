# Contact mechanics evidence

Mechanics ranks geometrically detected contacts. It never creates, deletes, or
moves a contact. Geometry from the source surface remains ground truth.

## Inputs and statuses

`ContactCandidate` describes paired source skin and environment observations:
world-space points and normals, friction model, reconstruction bound, sticking
or sliding mode, and optional stable sample indices. If the skin/surface gap
exceeds the reconstruction bound, no force hypothesis may bridge it.

`explain_contacts(contacts, wrench, origin=..., uncertainty=...)` tests whether
the required six-dimensional net wrench lies in the cone generated by each
contact subset. Moments use the explicit fixed origin. With uncertainty:

- `feasible` means every wrench in the uncertainty box is admissible;
- `infeasible` means at least one inequality excludes the entire box;
- `uncertain` proves neither statement.

The result retains all minimal feasible sets and per-contact roles:
`necessary_support_candidate`, `optional_contact`, `geometry_rejected`, or
`unexplained`. Redundant supports are not discarded. Candidate count is bounded
because subset enumeration is exponential.

## Timeline and object control

`contact_temporal.explain_support_timeline` keeps every least-switching path
through feasible sets. It is a continuity prior, not a load estimator and not a
minimum-duration filter; infeasible frames stay unresolved.

`object_control.observe_object_control` promotes control only when independent
source material points follow the same rigid, unscaled moving object within the
declared metric uncertainty. Proximity, stationary touching, one-frame glimpses,
and slipping remain undecided. Unexplained contacts stay protected.

## Limits

This is source feasibility evidence, not a robot controller check. It does not
solve contact forces, infer load percentages, verify actuator or torque limits,
or prove robot reachability. Those remain separate questions.
